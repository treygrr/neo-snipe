# content — the script that runs on every neopets.com page

Scans the page for item art, hangs a plain-DOM 🔍 badge on each one, and shows a bottom-right launcher.
Vue + Vuetify load only on first use — a badge click, the launcher, or the toolbar's `OPEN_PANEL`
message — and that mounts the popover into a shadow root so none of the extension's CSS reaches Neopets.

Sequence: `run()` calls `scan()` → `findItemElements` + `describeItem` (detect.js) → `addBadge` (badge.js)
→ on click `activate()` → `ui()` loads the bundle and calls `mountPopover` (mount.js) → `store.openFor`.

Injects its own scoped `<style>`. |
| `launcher.js` | The bottom-right bar: `addLauncher(onActivate)`, `setLauncherOpen(open, view)` (the bar's `data-open` flag, and `aria-pressed` on the button for the open view), `setLauncherDraggable`, `resetLauncherPosition`, `setLauncherIconSteps({ horizontal, vertical })` (the `launcherIconStep`/`verticalIconStep` settings through `lib/launcher-size.js`: the horizontal glyph size is the bar's `--ns-i` custom property, with buttons 6px and the bar 14px bigger; the vertical one sets `vButton`, applied straight away and re-clamped). Eleven children, left to right — `-grip` (the drag handle, hidden when `movableLauncher` is off), `-fav`/`-dailies`/`-foodclub` (open their views), `-sw`/`-ssw` (each opens its search panel; SSW hidden without Premium via `setLauncherPremium`), `-quests` (opens the Quest Log view; `setQuestCount` puts the ready-to-claim count on its corner), `-magma` (a link to the pool, so Ctrl/middle-click opens it; a plain click goes to `onMagmaClick`, which opens the `magma` log view; `setMagmaState` off/idle/loading/found; registered in `viewButtons` so it takes `aria-pressed` like the view buttons), `-inv` (a plain link to `INVENTORY_URL`), `-settings` (opens the settings view) and `-toggle`. Every button between the grip and the arrow is also dragged into a new order, always (`onButtonPointerDown`, ids from `LAUNCHER_BUTTONS` in `lib/tab-order.js`): past `DRAG_THRESHOLD` it moves among the visible buttons along the bar's axis, with no pointer capture so link clicks keep their Ctrl/middle-click behaviour; the click ending a drag is swallowed, and `onLauncherReorder(fn)` receives the new order; `setLauncherOrder(saved)` applies one via `fullOrder`, so hidden SSW/Magma buttons keep their place. Every view button is built by `viewButton()`, toggles its view (the open view's button closes the panel, another switches it) and is guarded by `suppressClick`. `-toggle` collapses the bar via `data-collapsed`: only the grip, the arrow and a notice stay, the rest folding away animated (width, gap and fade over `FOLD_MS`, then `visibility: hidden` so they leave the tab order; no animation under reduced motion); its chevron, `aria-expanded`, title and label follow the state. Collapsed is never stored — every load starts expanded — and it leaves an open panel open. Expanding a moved bar re-clamps it on screen without saving. Every re-clamp and drag start reads the bar's place from `position()` (the inline left/top, or `offsetLeft`/`offsetTop`), not from a measured rect, because a rect includes the 1px hover lift and made the bar creep upward. `setLauncherVertical(on, { restore })` (the `verticalLauncher` setting) stands the bar up via `data-vertical`: a column docked flush against the page edge (`data-side` left/right, only `top` inline), caret on top and grip below it by CSS `order`, every button `--ns-v` square — `vButton`, its glyph plus `V_PAD` (42px around the default 32px glyph, against the horizontal default 26/20) unless `fitVertical()` shrinks it to fit the window's height (re-run on resize, Premium and Magma visibility changes). It starts collapsed, and collapsed shows only the caret (the grip folds too, by height); the caret points into the window to open and at the edge to close, and is the only thing that hides or shows it. A drag undocks it while moving and snaps to the nearer side on release, saving that edge's x; restore picks the side from the saved x. Expanding re-clamps a column that would run off the bottom and folding returns the caret to `dockedY`. The bar carries `data-settling` (hidden, no transitions) from creation until the first `restorePosition`, so a vertical bar does not flash up horizontal; a 1.5s fallback clears it. `showLauncherNotice` pops a message above the bar (beside it when docked). SVG glyphs are built as nodes, not `innerHTML`. Clamping and saved position via `lib/positions.js`. |

## Rules worth knowing

- **Never use Neopets' `obj_info_id`** as a Jelly Neo id — the two numbering schemes are unrelated and
  produce confidently wrong items. Always resolve by name + image hash.
- `itemNameFor` returns `null` rather than guessing; `scan()` then marks the element `skip` so it is not
  re-examined on every mutation.
- Inside a shadow root `:root` matches nothing, so `mount.js` rewrites it to `:host` and also steals
  Vuetify's theme `<style>` out of `document.head` — skip either and hovers render as a black wash.
- The same gap bites `box-sizing`: Vuetify's reset is `* { box-sizing: inherit }` under an `html` set to
  border-box, and no `html` exists in a shadow root. Without `.ns-root { box-sizing: border-box }` every
  component inherits the page's content-box — compact fields come out 16px tall, `width: 100%` overflows.
- Badges, the launcher and the NP counter rewrite must stay plain DOM: they run on every page, so
  nothing here may import Vue.
- The launcher's artwork is inlined from `icons/` at build time, never hot-linked: Neopets moving an
  asset path would leave the buttons blank, and the SSW vector is rendered down to a 40 px PNG first
  so every page is not carrying 49 kB of detail drawn at 20.
- Drag hangs off `.neosnipe-launcher-grip`, not the bar or a button. A pointer capture retargets the ending
  click to whatever took the capture, so capturing on the bar swallows its buttons' clicks — and
  leaving the inventory link uncaptured is what keeps ctrl-click and middle-click working.
